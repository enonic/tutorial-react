In this chapter you will create a local Enonic instance with sample content, and run your first query against the GraphQL API.

== Task: Install the Enonic CLI

The Enonic CLI manages local instances of Enonic XP, known as sandboxes.

. *Install the CLI* - Run this command in your terminal:
+
[source,shell]
----
npm install -g @enonic/cli
----
+
There are https://developer.enonic.com/start[alternative ways to install the Enonic CLI] as well.

. *Verify the installation* - Run `enonic -v`, which prints the version of the CLI. This tutorial expects version 4 or newer.

== Task: Create and start a sandbox

. *Create a sandbox* - Run this command to create a sandbox called `+react_tutorial+`:
+
[source,shell,subs="attributes+"]
----
enonic sandbox create react_tutorial -t intro -v {xp-release} -f
----
+
This command will:
+
* create a sandbox running Enonic XP {xp-release}
* use the `intro` template, which installs Content Studio, Guillotine and the Intro app with its sample content
* accept default values for the remaining options (`-f`), and start the sandbox

. *Wait for the sandbox to start* - The first startup takes a little longer, as the applications are installed and the sample content is imported and published.

. *Verify that the sandbox is running* - Open http://localhost:8080[http://localhost:8080]. The Enonic XP welcome page appears.

Leave the sandbox running in this terminal window for the rest of the tutorial. To stop it, press ctrl-c. To start it again, run `+enonic sandbox start react_tutorial+`.

== Task: Open Content Studio

. *Log in* - On the welcome page, click *Log In as Guest* to open the XP admin dashboard.
. *Open Content Studio* - Select it from the `XP menu`. The `Intro Project` opens automatically.
. *Verify the sample content* - The content tree lists the `Persons` and `Movies` folders, among others.

The project contains persons and movies, along with their images. This is the content your React application will list and present. All of it is already published.

== Task: Run a query

Guillotine is Enonic's GraphQL API. Content Studio includes Query Playground, a tool for writing and testing queries against it.

. *Open Query Playground* - Click `Query Playground` in the Content Studio menu.
. *Paste and run the query below* - It retrieves the three most recently modified persons:
+
[source,graphql]
----
query PersonListQuery {
    guillotine(project: "intro", branch: "master") {
        queryDsl(
            first: 3
            query: {
                term: {
                    field: "type",
                    value: {
                        string: "com.enonic.app.intro:person"
                    }
                }
            }
            sort: {
                field: "modifiedTime",
                direction: DESC
            }
        ) {
            _id
            _name
            displayName
            type
        }
    }
}
----

. *Verify the response* - The response panel shows this result:

[source,json]
----

In the query:

* `intro` is the identifier of the content project
* `master` is the branch holding published content, while `draft` holds work in progress
* `com.enonic.app.intro:person` is the `person` content type, defined by the Intro app

== The API endpoint

Query Playground is a convenience for developers. Your React application will send the same queries directly to the Guillotine endpoint:

[source,text]
----
http://localhost:8080/api/com.enonic.app.guillotine:graphql
----

The endpoint is shared by all content projects, which is why each query states the project and branch. Published content in the Intro project can be read without logging in, so the application needs no credentials.
