In this chapter you will create a React application with TypeScript, connect it to the Enonic API, and add routing.

== Task: Create the project

. *Scaffold the app* - With the sandbox running, open a new terminal window in the folder where you keep your tutorial projects, and run this command:
+
[source,shell]
----
npm create vite@9 tutorial-reactspa-frontend -- --template react-ts
----
+
This creates a Vite project with React and TypeScript in a new folder called `tutorial-reactspa-frontend/`.

. *Install the dependencies* - Enter the new folder and install:
+
[source,shell]
----
cd tutorial-reactspa-frontend

npm install react-router-dom sass @enonic/react-components
----
+
This installs the dependencies of the project template, and adds:
+
* `react-router-dom` for routing between the pages of the application
* `sass` for the stylesheets used in this tutorial
* `@enonic/react-components` for rendering rich text from Enonic

. *Start Vite* - Run this command from the `tutorial-reactspa-frontend` folder:
+
[source,shell]
----
npm run dev -- --port 3000
----

. *Verify the app* - Open http://localhost:3000[http://localhost:3000]. It shows the start page of the project template:
+
image::react-app.png[The start page of the Vite project template,width=75%]

Leave Vite running. It updates the page in the browser whenever you change a file. To stop it, press ctrl-c.

To resume the tutorial later, start the sandbox with `+enonic sandbox start tutorial_reactspa+`, then run the command above again from the `tutorial-reactspa-frontend` folder. All file paths in this tutorial are relative to that folder.

== Task: Connect to the API

The application runs in the browser and fetches content directly from {guillotine-docs}[Guillotine]. During development, the application and Enonic run on different ports. To keep all requests on the application's own origin, Vite will forward them to Enonic.

. *Add a proxy* - Replace the contents of `vite.config.ts` with the following:
+
.vite.config.ts
[source,typescript]
----
include::{sourcedir}vite.config.ts[]
----
+
Vite now forwards every request starting with `/api` to the sandbox. This covers both the GraphQL endpoint and the images it refers to. To use an Enonic instance on another address, set `+ENONIC_URL+` in `.env`.

. *Set the endpoint* - Create a file called `.env` in the `tutorial-reactspa-frontend` folder:
+
..env
[source,properties]
----
VITE_GUILLOTINE_URL=/api/com.enonic.app.guillotine:graphql
----
+
The value is relative, so the browser sends requests to the application's own origin, where the proxy picks them up.

. *Verify the configuration* - Check the terminal where Vite is running. It reports that both files changed, and that the server restarted:
+
[source,text]
----
[vite] vite.config.ts changed, restarting server...
[vite] server restarted.
[vite] .env changed, restarting server...
[vite] server restarted.
----

WARNING: Vite includes `+VITE_+` variables in the code sent to the browser. Never use them for credentials or other secrets.

NOTE: The proxy only exists during development. In production, either route `/api` to Enonic on the host serving the application, or build with an absolute endpoint URL and configure {guillotine-docs}/configuration[CORS in Guillotine].

. *Replace the contents of `src/App.tsx`* - Use a router that has a single route:
+
.src/App.tsx
[source,typescript]
----
import './App.sass';
import {Route, BrowserRouter as Router, Routes} from 'react-router-dom';

export default function App() {
  return (
    <Router>
      <Routes>
        <Route path="*" element={<p>Hello router!</p>}/>
      </Routes>
    </Router>
  );
}
----

. *Remove the files you no longer need* - Delete `src/App.css` and the `src/assets/` folder. The new `App.tsx` does not use them.

. *Verify the result* - Your browser now displays the text `Hello router!`.
