In this chapter you will create a `Person` component that displays the details of a single person, including the biography, which is rich text.

== Task: Add the query

. *Add the query* - Create the following file:
+
.src/queries/Person.ts
[source,typescript]
----
include::{sourcedir}src/queries/Person.ts[]
----
+
The query takes the ID of the person as a variable. The `bio` field is rich text: besides the HTML in `processedHtml`, the query requests the `links`, `images` and `macros` the HTML refers to. You will put them to use in the following chapters.
+
The `processHtml` argument controls the images in the HTML. `imageSrcWidth` sets the width of the default image, while `imageWidths` and `imageSizes` produce the `srcset` and `sizes` values for responsive images.

. *Verify the query* - Copy only the text between the backticks into Query Playground, add `{"personId": "a8b374a2-c532-45eb-9aa1-73d1c37cd681"}` in the variables panel, and run it. The response contains Léa Seydough, with her biography in `processedHtml`.

The component reads the ID of the person from the URL, fetches the person and renders the name, the biography and the photos.
+
The biography is rendered by the `RichText` component from `@enonic/react-components`. It needs three things:
+
* `data` is the rich text value, exactly as returned by Guillotine
* `meta` describes the content the rich text belongs to
* `component` describes where the rich text is used. This application has no page components, so a minimal content type entry is sufficient

. *Add the route* - Update `src/App.tsx` with a route for the component:
+
.src/App.tsx
[source,typescript]
----
import './App.sass';
import {Route, BrowserRouter as Router, Routes} from 'react-router-dom';
import {PersonList} from './components/PersonList';
import {Person} from './components/Person';

export default function App() {
  return (
    <Router>
      <Routes>
        <Route path="/" element={<PersonList />}/>
        <Route path="/p/:name/:personId" element={<Person />}/>
      </Routes>
    </Router>
  );
}
----
+
The name makes the URL readable, while the ID is what the component uses to fetch the person.

. *Verify the result* - Open http://localhost:5173[http://localhost:5173] and click a person, or go directly to http://localhost:5173/p/lea-seydough/a8b374a2-c532-45eb-9aa1-73d1c37cd681[Léa Seydough]:
+
image::person-details.png[The person details page with the biography partly rendered,width=1200]

The text of the biography is in place, but the image in it is missing, the links do not work, and an error message is shown in the middle of the text. Guillotine does not know where your application serves images and pages, so the HTML only contains placeholders for them. Resolving the placeholders is the job of your application.
