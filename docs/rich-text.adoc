= The Rich text component
:sourcedir: ../
:imagesdir: media/

In this chapter we'll look at how you can take control over the Enonic's rich text component.

== Background

The RichText component is able to output HTML, and comes with basic handling of links and images.

Guillotine 9 returns `processedHtml` with placeholders for internal links and images, plus structured `links` and `images` entries containing their URL data. The placeholders are not usable browser URLs. `RichText` forwards the original matching entry to each renderer as `data`; custom `Image` and `Link` components must resolve it for our app.

The `Person` query already requests these entries and sets `processHtml.imageSrcWidth: 768`, `imageWidths: [400, 800, 1200]`, and `imageSizes: "(max-width: 800px) 100vw, 800px"` explicitly. These select the fallback image width, responsive widths, and HTML `sizes` value. Keep these options when adapting the query.

== Links

The `Link` component is used by `RichText` to correctly resolve and render links inside an HTML content.

The default implementation uses the HTML `href`, but cannot resolve Guillotine 9's internal link placeholders. The custom renderer below will make the Daniel Carrigear link in http://localhost:3000/p/lea-seydough/a8b374a2-c532-45eb-9aa1-73d1c37cd681[Lea Seydough's^] biography work in our React app.

Our goal is to change internal person links to be in the format `/p/:name/:personId` - so they will be rendered by the React application instead.

- For media content, we resolve `data.media.mediaUrl` through the `mediaUrl` helper.
- Ordinary links without structured `data` keep their HTML `href` unchanged.
- Unsupported internal content or references without a usable destination render as plain text.
