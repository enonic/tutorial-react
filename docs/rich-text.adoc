In this chapter you will make the links and images in the biography work, by giving the `RichText` component your own renderers.

== Background

Rich text in Enonic may contain links to other content, links to media, and images. In the response from Guillotine, each of them is represented twice:

* as an element in `processedHtml`, carrying a reference
* as an entry in `links` or `images` with the same reference, holding the details: the content a link points to, or the URL parts of an image

`RichText` matches the two. For every link and image in the HTML, it calls a renderer and passes the matching entry as `data`. The default renderers output the HTML as it is. By supplying your own, you decide what each link and image becomes in your application.

The renderer handles four cases:
+
* An ordinary link, such as an external URL, has no `data` and is rendered unchanged.
* A link to media is resolved with the `mediaUrl` helper.
* A link to a person becomes a router link to `/p/<name>/<id>`, built from `+_name+` and `+_id+` of the content. The application handles the navigation without reloading the page.
* A link to other content is rendered as plain text, since the application has no page to show it.
