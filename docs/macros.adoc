= Rendering macros
:sourcedir: ../
:imagesdir: media/

In this chapter you will render a macro, which is a custom component placed inside rich text.

== Background

Macros let editors insert more than text, links and images into rich text. Each macro is defined by an application, and has its own configuration and optionally a body.

The Intro app defines a macro called `factbox`, which is used in the biography of Léa Seydough. Guillotine returns it in the `macros` field of the rich text, and `RichText` calls a `Macro` renderer for it. Without one, it renders an error message:

image::no-macro.png[width=1200]

TIP: Macros are described in the https://developer.enonic.com/docs/xp/stable/cms/macros[XP documentation].

`RichText` uses a single renderer for all macros. It identifies each macro by its descriptor, and passes the configuration as `data`. The renderer maps `com.enonic.app.intro:factbox` to the `FactBox` component.

For any other macro, the renderer throws an error. `RichText` catches it and renders an error placeholder in place of the macro, without affecting the rest of the text.

== Passing props to the renderers

A renderer may need values from the component that uses `RichText`. Any additional prop you give `RichText` is passed on to the `Image`, `Link` and `Macro` renderers.

To do this with type safety, declare the additional props as a type:

.src/components/RestProps.ts
[source,TypeScript]
----
export type RestProps = {
    personId: string
};
----

Use the type when declaring each renderer, which makes the props available in it:

[source,TypeScript]
----
export const Link: LinkComponent<RestProps> = ({children, data, href, target, title, personId}) => {
    // ...
};
----

Then supply the type and the values to `RichText`:

[source,TypeScript]
----
<RichText<RestProps>
    data={bio}
    meta={meta}
    component={component}
    Image={Image}
    Link={Link}
    Macro={Macro}
    personId={personId}
/>
----
